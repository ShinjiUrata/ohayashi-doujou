# 譜面編集画面

## 概要

録音直後の譜面プレビュー、メタデータ入力(譜面名・地域名)、試遊、および公開への導線。
制作モードのハブ画面。**編集・試遊はすべて無料**、課金は次画面(公開)のみで発生する。

## 主要 UI 要素

- メタデータ入力フォーム
  - 譜面名(`name`) — 例: 「獅子舞 入り囃子」
  - 地域名(`region`) — 例: 「下田町」
- ノーツリスト(時系列表示)
  - 時刻(mm:ss.SSS)
  - 種別バッジ(don_l / don_r / ka_l / ka_r)
  - (将来)個別ノーツの微修正 UI
- ボタン
  - **試遊** → プレイ画面(04)でこの譜面をローカル再生
  - **保存** → 端末ローカルに保存、譜面一覧(02)へ
  - **公開** → 公開画面(08)へ(課金が必要)
  - **破棄** → ドラフトを削除

## ユーザーができること

- 譜面名・地域名を入力
- ノーツの時系列を確認
- (将来)ノーツの微修正 — 位置調整・種別変更・削除
- 試遊(ローカル完結、無料)
- ローカル保存(公開しなくても保持可能、無料)
- 公開画面へ遷移(課金フローへの入口)

## データ

- ドラフト譜面 JSON を入力として受け取り、編集後は同じ JSON を上書き
- 保存時に確定した `id`(ローカル用の UUID や仮 ID)で `{id}.json` としてアプリ専用サブディレクトリに書き出す
- 公開時の ID(サーバー上のグローバル ID)は公開画面(08)で改めて指定する
  - ローカル ID とサーバー ID は別概念

## 必要な API / 通信

編集自体では通信なし。公開画面(08)へ遷移した後に `POST /check-id` などが発生。

## 周辺技術

- SwiftUI(`Form`, `TextField`, `List`)
- `JSONEncoder` / `JSONDecoder`
- `FileManager` でローカル保存

## 無料でできることの境界

CLAUDE.md §3.8 の設計方針:
- 録音・編集・ローカル試遊は **すべて無料**
- サーバーへのアップロード(公開)のみが課金対象
- ここで自由に修正・試遊を繰り返せることが、心理的納得感を生む

## 遷移元 / 遷移先

- **遷移元**:
  - 録音画面(06)から録音停止時
  - 保存済み譜面一覧(02)から「編集」(将来対応、MVP では未定)
- **遷移先**:
  - 「試遊」→ プレイ画面(04)、終了後この画面に戻る
  - 「保存」→ 保存済み譜面一覧(02)
  - 「公開」→ 公開画面(08)
  - 「破棄」→ タイトル/メニュー(01)
