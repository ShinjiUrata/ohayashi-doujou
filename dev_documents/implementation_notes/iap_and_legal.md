# 課金・法務 — 気をつけること

**位置付け**: 譜面公開時の IAP 実装と、それに伴う法令(資金決済法・特商法)、Apple ガイドラインへの適合を担保するための注意点。

**関連**:
- 実装手順: `dev_documents/implementation_plan/ios.md` §12, §15、`dev_documents/implementation_plan/backend.md` §6, §7、`dev_documents/implementation_plan/others.md` §3, §12-14
- Apple 審査: `dev_documents/implementation_notes/apple_review.md`
- CLAUDE.md §3.8「譜面共有 / IAP」

---

## 1. 資金決済法「前払式支払手段」該当性の維持

**根本方針**: 現在の設計は「Consumable + 購入と役務提供が同時」= 資金決済法の**規制対象外**。この設計を崩す機能追加を絶対にしない。

**該当してしまう危険な設計変更**:
| 危険な変更 | 理由 |
|---|---|
| **クレジット制の導入**(¥1,000 で1回分クレジット → 後で消費) | 前払式支払手段に該当 → 供託義務・有効期限管理が必要になる |
| **サブスクリプション化** | 継続的役務 → 別の規制枠 |
| **返金 / 保留機能の実装** | 「役務提供が同時」の建付けが崩れる |
| **公開せずに「予約公開」** | 課金時点で役務提供が完了しない |

**対策**:
- CLAUDE.md §9「判断ログ」に記載済み。新機能追加時は本ドキュメントを再読
- 「クレジット」「チケット」「ポイント」等の名称を新機能で使わない
- 課金は必ず「公開ボタン押下 → 決済成功 → その場で publish」の順序を守る

---

## 2. 特商法表記の必須項目チェック

**問題**: 特商法表記が欠けると、消費者庁からの是正指導、App Store 審査でのリジェクトのリスク。

**必須項目**(全て記載):
- [ ] 販売事業者名(法人名)
- [ ] 所在地(法人登記の住所)
- [ ] 代表者名
- [ ] 連絡先(電話番号 + メールアドレス)
- [ ] 商品名(「譜面公開サービス」等)
- [ ] 販売価格(¥1,000、税込表記)
- [ ] 支払方法(Apple 決済 / App Store)
- [ ] 商品引き渡し時期(決済完了後即時)
- [ ] 返品・キャンセル条件(原則不可、理由の明記)
- [ ] 動作環境(iOS 17 以上)

**注意点**:
- 表記は日本語必須
- URL を App Store Connect に登録(iOS アプリのメタ情報)
- 更新時は「最終更新日」を残す
- 弁護士レビュー推奨

---

## 3. 利用規約の必須項目

**問題**: 利用規約が不十分だと、公開者・プレイヤー間のトラブル時に責任が事業者に飛ぶ。

**必須項目**:
- IAP に関する規定
  - Consumable(消費型)である旨
  - 購入後の返金は原則不可(Apple 経由の返金のみ受け付ける)
  - 課金後の技術的トラブル時の対応方針
- 譜面公開ポリシー
  - **公開者が著作権侵害の責任を負う旨の明記**
  - 事業者側が判断で取り下げる可能性
  - 譜面 ID の推測アクセスは仕様として許容している旨
- 譜面 ID の重複競合が稀に発生する旨と対応方針
- 免責事項(祭り会場での使用など)
- 準拠法・裁判管轄
- 変更通知(規約更新時の連絡方法)

---

## 4. Consumable 性質の説明準備

**問題**: App Store 審査で「実質サブスクリプション」「Non-Consumable と実態が違う」と指摘されるリスク。

**対策**:
- 説明を用意:
  - 「1曲公開 = 1つの成果物 = 1回の役務」
  - 「同一の公開行為は再度実行できない(一度公開したら取り消せない/再公開もない)」
  - 「サーバー配信は publish の副次的結果、継続的サービス提供ではない」
- Review Notes にこの説明を書く

---

## 5. 返金対応

**問題**: ユーザーが Apple 経由で返金を得た後、譜面はサーバーに残っている状態。

**対策**:
- **弊社から直接返金しない**(すべて Apple 経由)
- Apple から返金通知(App Store Server Notifications V2)を受けたら:
  - **MVP**: 通知を受け取るだけ、譜面はそのまま残す(少額のため運用コストを抑える)
  - **Phase 6+**: 自動取り下げする運用検討(Firestore の `charts.{id}.status` を `withdrawn` に)
- Notifications V2 の受信エンドポイントを Cloud Run に用意する(Phase 6+ 実装、MVP は未対応でも Apple ガイドライン違反ではない)
- 利用規約に「返金時の譜面の扱い」を明記

---

## 6. 「更新公開機能」を絶対に作らない

**問題**: ユーザーから「¥1,000 で公開したけど、ミスに気づいた。無料で修正したい」という要望が来る可能性が高い。

**対策**:
- 一律「別 ID で新規公開してください」で対応
- CLAUDE.md §9 の判断ログに明記済み
- 修正無料化を許すと「取り下げ→再公開」による課金回避の抜け道になる
- UX を優しくするため、公開前の「試遊」で十分確認できる導線をより丁寧に

---

## 7. IAP プロダクト名のローカライズ

**問題**: プロダクト名が曖昧だと、ユーザーが購入内容を誤認する可能性。

**対策**:
- Display Name: **「譜面を公開する」**(明確)
- Description: **「1曲分の譜面をサーバーに公開して、他のプレイヤーがダウンロードできるようにします」**(範囲を明示)
- 「クレジット」「利用権」等の継続的な表現を使わない

---

## 8. 税務・会計

**問題**: ¥1,000 の内訳と、Apple 手数料の扱いを事前に理解しておかないと会計処理でトラブル。

**対策**:
- Apple 手数料: 通常 **30%**、Small Business Program 適用で **15%**
  - 弊社の年間 App Store 売上が $1M 未満なら申請可能
  - `spanglow`(afterglow アプリ)を含めた法人合算での判定
- 手取り: ¥1,000 × 70% = ¥700(通常)or × 85% = ¥850(SBP)
- 消費税: 内税(¥1,000 に含まれる)として扱う
- 会計仕訳: Apple からの入金は月次で個別トランザクションが見えるため、Firestore と突合

---

## 9. 販売地域の制限

**問題**: 海外ユーザーが購入したがサーバーが日本語しか対応しないなどのトラブル。

**対策**:
- MVP は App Store Connect の Pricing and Availability で **日本のみ** を選択
- 海外展開は将来検討(ローカライズ + 特商法相当の各国規制対応が必要)

---

## 10. 未成年者の誤課金防止

**問題**: 祭り会場で子供が誤って「公開ボタン」を押してしまう。

**対策**:
- **公開ボタンをタイトル画面から見て奥深くに配置**(3タップ以上)
  - 現在の設計: タイトル → 録音 → 編集 → 公開(4画面)
- 公開画面には「¥1,000 が課金されます」の警告を明示
- Apple 標準の Ask to Buy(ファミリー共有時の親承認)に依拠
- Guided Access(iOS の設定)使用を会場運用マニュアルで推奨
  - Guided Access 中は IAP ダイアログを表示しない設定にできる

---

## 11. 「事前予告なしに公開停止」の可能性を明記

**問題**: 譜面が予告なく取り下げられた際にユーザーから苦情が来る。

**対策**:
- 利用規約に「事業者判断で予告なく取り下げる場合がある」旨を明記
- 取り下げ理由の説明義務は基本負わない旨も明記(著作権判断等の公表がプライバシー問題を生むため)
- ただしユーザーの問い合わせには誠実に応答

---

## 12. 特商法・利用規約・プライバシーポリシーの配置

**問題**: URL リンクが切れたり、App Store 審査時に URL がアクセス不能だと審査落ちる。

**対策**:
- 3 文書とも公開可能な URL に配置(GitHub Pages / GCS 公開バケット / 独自ドメイン)
- App Store Connect のメタ情報に登録
- アプリ内の設定画面からもリンク可能に(Phase 6 の設定画面追加時)
- 定期的に URL アクセス確認(月次)

---

## 13. サーバー障害時の課金トラブル

**問題**: IAP 決済は成功したが Cloud Run で `/publish` が失敗した場合、ユーザーは「¥1,000 払ったのに公開されない」状態。

**対策**:
- **StoreKit の Transaction.finish() を publish 成功後にのみ呼ぶ**(iOS 側)
- 未 finish のトランザクションは次回起動時に `Transaction.updates` で再送
- サーバー側は冪等性を担保(同 transaction_id で再送されても正しく処理)
- 万一の恒久的失敗時は、Apple のカスタマーサポート経由で返金対応をユーザーに案内(利用規約に明記)

---

## 14. 譜面公開者への表示

**問題**: 「あなたの譜面は現在公開されていません」など、状態を分かりやすく伝える必要がある。

**対策**:
- ローカル譜面一覧(02)にステータス表示:
  - `ドラフト`(未公開)
  - `公開済み`(サーバーにある)
  - `取り下げ済み`(サーバーから削除)
- 取り下げ時の再公開は不可、別 ID で新規公開

---

## 15. Small Business Program 申請

**問題**: 年間 App Store 売上 $1M 未満なら手数料 15% に下げられるが、忘れると 30% のまま。

**対策**:
- App Store Connect の Apple Small Business Program に申請(既存 app のプロダクション後になる場合あり)
- `spanglow` を含めて法人合算判定なので、事前に売上見込みを確認
- 毎年 12 月末に再判定
