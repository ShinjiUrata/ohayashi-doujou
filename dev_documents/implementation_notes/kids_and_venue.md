# 子供向け UI / 祭り会場運用 — 気をつけること

**位置付け**: 本アプリのコアユーザー(祭り会場の子供たち)と、実運用シーン(ブース設置された 1 台の iPhone)を前提とした UX・運用注意点。

**関連**:
- 全体設計: CLAUDE.md §1「利用シーン」
- 実装手順: `dev_documents/implementation_plan/ios.md` §19
- 画面設計: `dev_documents/screens/`
- iOS 落とし穴: `dev_documents/implementation_notes/ios_pitfalls.md` §17(スリープ抑制)

---

## 1. タップ領域のサイズ

**問題**: Apple HIG の最小 44pt では子供(特に幼児)には狭い。誤タップ率が上がる。

**対策**:
- 主要 CTA(プレイ、判定ゾーン、リザルトの「もう一度」)は **60pt 以上**
- 太鼓の面全体を大きくして、少々ズレても認識できるように
- 判定ゾーンは 3 区分(左外 / 中央 / 右外)で幅を等分ではなく、中央を広く(実際に叩く位置は太鼓の中心が多いため)

---

## 2. 誤操作による課金導線

**問題**: 子供が誤って公開ボタンをタップし、¥1,000 の課金が発生する。

**対策**:
- 公開画面までの導線を **タイトルから 3 タップ以上**深くする
  - 現状: タイトル → 録音 → 編集 → 公開(4 画面)
- 公開ボタンは目立たない位置(画面下端 or 別タブ)に
- 公開ボタン押下時に「¥1,000 の課金が発生します」の明示的確認ダイアログ
- Apple 標準の Ask to Buy(ファミリー共有時の親承認)に依拠

---

## 3. Guided Access(iOS 標準機能)の活用

**問題**: 会場設置時、子供が App Store や設定アプリを開いてしまう。

**対策**:
- **Guided Access モードでアプリを固定**
  - iOS 設定 → アクセシビリティ → Guided Access → ON
  - 起動: サイドボタン 3 回押し
  - 終了: 事前設定したパスコード or Face ID
- Guided Access 中は:
  - アプリ切替不可
  - ホーム画面に戻れない
  - 一部のタップ領域を無効化できる(公開ボタンを無効化するオプションもあり)
- 端末オーナー(自治体担当者)が事前設定
- 会場設営マニュアルにこの手順を記載

---

## 4. 音量とサイレントモード

**問題**: 子供がマナーモードで持って来た iPhone や、会場のスピーカーで音を出したい場合の対応。

**対策**:
- AVAudioSession カテゴリ `.playback` を採用(マナーモードでも音が出る)
- ボリューム調整はアプリ内 UI を作らず、本体の音量ボタンで統一
- 会場設置時は本体音量を最大にする(マニュアルに記載)
- 外部スピーカー接続時も自然に対応(iOS 自動)

---

## 5. スリープ・電源管理

**問題**:
- プレイ中に自動スリープに入って画面が消える → 体験中断
- 常時抑制するとバッテリー消耗が激しい

**対策**:
- **プレイ中のみ** `UIApplication.shared.isIdleTimerDisabled = true`
- タイトルに戻ったら false に戻す
- 会場設置時は電源接続 or モバイルバッテリー(マニュアル記載)
- 一定時間(10 分)無操作でタイトルに自動戻り(次のプレイヤーへの引き継ぎ)

---

## 6. 端末発熱

**問題**: SpriteKit + AVAudioEngine + Haptics + 連続タッチで CPU/GPU が稼働、発熱でパフォーマンス低下や自動シャットダウンのリスク。

**対策**:
- 数時間連続プレイのテスト実施(実運用相当)
- 発熱時にゲーム挙動が悪化しないか観察
- 会場は屋外(夏祭り)の可能性、直射日光下は絶対に避ける
- 端末ケースの通気性を確保(マニュアル記載)

---

## 7. 物理的な保護

**問題**: 子供が乱暴に扱う、落とす、飲み物をこぼす。

**対策**:
- 落下対策の頑丈なケース(ラギッドタイプ推奨)
- スタンド or 固定台(壁面固定 or デスクマウント)
- 会場運用マニュアルに端末保護方法を記載
- 予備端末を用意(1 台故障時の即応)

---

## 8. 「次のプレイヤーへの引き継ぎ」の設計

**問題**: 前のプレイヤーが録音モードや編集画面で終わっていると、次の子供がプレイできない。

**対策**:
- リザルト画面 → 「もう一度」/「一覧に戻る」→ 数秒後に自動でタイトルに戻る
- 録音・編集画面は Guided Access で無効化する運用も検討(祭り会場では制作機能不要)
- 会場運用時は「プレイモード専用」の起動オプションを検討(Phase 6+ で実装余地)

---

## 9. 譜面選択のシンプルさ

**問題**: 譜面が 3 曲以上ある時、子供が選択に迷う。

**対策**:
- ライブラリのカードは大きめに(1 画面に 3-4 個)
- 名前 + 地域名で明確に区別
- Phase 7 で試遊 → デフォルト譜面を絞る(1-2 曲でスタート、複数曲は将来)

---

## 10. 判定窓の緩さ

**問題**: 大人向けの厳しい判定窓では子供が「不可」ばかりで嫌になる。

**対策**:
- 初期値: 良 ±200ms / 可 ±400ms(CLAUDE.md §3.5)
- Phase 7 で実際の子供に試遊してもらって調整
- 「不可」が続くと悲しい体験になるので、緩めが良い
- Phase 6+ で「難易度」設定を UI に出す余地あり

---

## 11. 判定文字の分かりやすさ

**問題**: 「良」「可」「不可」は漢字で子供に読めない可能性(小学校低学年以下)。

**対策**:
- 判定文字を漢字 + アイコンで表現
  - 良: ⭐️ + 「良!」(金色)
  - 可: ⚪️ + 「可」(銀色)
  - 不可: — (色薄め、あえて目立たせない)
- 効果音での区別(良は明るい音、不可は無音 or 弱い音)

---

## 12. スコアの見せ方

**問題**: 数字だけでは子供に伝わりにくい。

**対策**:
- リザルト画面で星評価(5 段階)を大きく表示
- スコア数字は補助的に
- 「みんな上手にできたよ!」等の褒めるコピー(将来検討)

---

## 13. アイコン・タイトル画面の親しみやすさ

**問題**: 大人向けの洗練されたデザインだと、子供が「難しそう」と感じる。

**対策**:
- 太鼓のイラストは丸みのある温かい表現
- 祭りらしい配色(朱・金)を明るめに
- 難しい漢字は使わない(「お囃子道場」の「囃」はふりがな付き検討)

---

## 14. 保護者・自治体担当者への配慮

**問題**: 保護者が「アプリで課金される?」と不安になる。

**対策**:
- App Store の説明文に明記:
  - 「ゲームプレイに課金は不要です」
  - 「¥1,000 の課金は譜面制作者向けの機能(自治体・指導者向け)」
- アプリ内 About 画面(将来)にも同趣旨を明記
- 会場ブースに「無料で遊べます」の掲示物

---

## 15. 会場での複数端末運用

**問題**: 混雑時に 1 台では待ち行列ができる。

**対策**:
- MVP は 1 台想定だが、複数台対応可能な設計(端末ごとに独立、通信なし)
- 複数台を並べる場合の推奨レイアウトをマニュアルに記載
- 譜面同期の必要なし(全端末が同じ譜面 JSON を持てば OK)

---

## 16. 電波状況とオフライン動作

**問題**: 祭り会場は電波が混雑してつながらない・遅い。

**対策**:
- **プレイ・録音は完全オフライン**(CLAUDE.md §1「オフライン動作前提」)
- 譜面 DL は事前に済ませておく(会場設営前)
- 会場運用マニュアルに「事前 DL を必ず実施」と記載
- 公開機能(要通信)は指導者が自宅・オフィスで実施

---

## 17. 譜面ダウンロードの事前準備

**問題**: 会場で「あ、この譜面まだ入れてなかった」となる。

**対策**:
- 会場運用マニュアルにチェックリスト:
  - [ ] 使用する譜面が全てローカルにあるか
  - [ ] 譜面が正しく再生できるか
  - [ ] 音量・触覚が動作するか
- 「保存済み譜面一覧」で全譜面が見えることを事前確認

---

## 18. アクセシビリティ

**問題**: 聴覚障害・視覚障害の子供にも遊べるように。

**対策**:
- MVP では最小限
- 触覚フィードバックが聴覚代替になる(打感で判定が分かる)
- 視覚的なフィードバック(判定リング光る)も同時に発火
- VoiceOver 対応は将来課題

---

## 19. プレイヤーの怪我・体調不良への配慮

**問題**: 熱中症、指の怪我、興奮しすぎ 等。

**対策**:
- ゲーム的な要素はあるが、長時間連続プレイを促す仕組みを作らない
- 「もう一度」ボタンは連打で疲れないよう配置
- 会場スタッフによる目視・声かけを推奨(マニュアル記載)

---

## 20. 会場運用マニュアルの整備

**問題**: 自治体担当者・祭りボランティアが誰でも運用できる必要がある。

**必要な項目**(別ドキュメントとして整備):
- 端末セットアップ手順(Guided Access、音量、電源)
- 事前譜面 DL 手順
- 動作確認チェックリスト
- 子供対応のポイント(順番待ちの誘導、故障時の対応)
- 端末故障時の予備切替手順
- 撤収時の手順
- 問い合わせ窓口(弊社サポート)

**Phase**: Phase 7(祭り運用準備)
